# Recorded-media transcription and reviewed provenance checkpoint

November 2, 2026. This extends the [recording checkpoint](recording-checkpoint.md). The full [50-capability objective](../product/acceptance-ledger.md) remains open. Authentication is deliberately deferred; all verification used loopback services and synthetic content in isolated test databases.

## Working chain

Complete encrypted WebM track → separately consented processing job → local FFmpeg PCM decoding → local whisper.cpp timestamped recognition → immutable review versions → verified speaker and patient context → patient-specific excerpt → structured response with exact source/version link → reviewed/signed form → deterministic draft note.

The recognizer does not infer patient identity. Reviewers explicitly select and verify a recorded participant as speaker and separately verify any patient context. A client's speech cannot be attributed to another patient. Excerpts require current patient-chart permission and the current approved transcript version. General group text is not automatically copied to individual charts.

Migration 013 adds `transcription_jobs`, `transcripts`, `transcript_versions`, and `transcript_excerpts` (38 public tables), plus the nullable `form_responses.transcript_excerpt_id` relationship. Migration 014 strengthens the database rule: the current-version pointer can advance only to its next child, never rewind. Organization/patient/encounter keys constrain the links. Initial recognition and previous correction versions are preserved; approval changes only draft review metadata. Patient excerpts are append-only. A corrected transcript invalidates its older excerpts for new form review/signing, note generation, and signing of a linked draft note. Previously signed records remain unchanged.

Every recorded client needs a current `transcription` consent in addition to the recording agreement. Jobs snapshot those consent records and recheck the requested operator's current role, encounter scope and exact consents at start, every two seconds, and before publication. Changed/revoked/expired consent blocks processing; historical access still requires current clinical/encounter scope. Jobs expose queued/running/ready/failed/cancelled states, with no fabricated progress percentage. Cancellation publishes no partial transcript. A database advisory lock selects one recording worker; the existing uploaded-WAV endpoint shares the process recognition semaphore. Interrupted running jobs become failed when the owning worker restarts; retry is explicit.

The custom review UI supports timestamp edits, uncertainty/exclusion, participant verification, patient context, correction reasons, history, explicit approval, and excerpt selection. Invalid times and unsaved-close attempts retain edits. Longer transcripts paginate five segments at a time; processing history collapses once text is available. Unsaved changes prevent the surrounding visit dialog from closing and disable room switching. Browser verification exercised segments 6–10 of the 95-segment result and the surrounding close guard. The form editor lists approved patient excerpts, fixes their visit context, and keeps source text read-only. Selecting a different linked excerpt clears answers and provenance in the editor; explicitly remapped answers survive saving and return to review. Transcript detail returns only the selected version's excerpts, scoped to the current patient's clinician or organization clinical lead/admin.

## Limits and next work

English recognition only; no automatic diarization, clinical accuracy benchmark, live transcription, semantic knowledge base, or model-generated clinical note yet. Manual verification is a local workflow attestation, not verified identity. The initial note is deterministic document assembly from signed answers. The broader note-generation and knowledge-base objectives remain open.

The decoder accepts at most 256 MiB / two hours, using at most 24 five-minute PCM slices; oversized media fails instead of silently truncating. Decoder timeout is 120 seconds and each recognition slice has a 180-second limit. Text, JSON and editable segment counts are bounded. Only the first audio stream is decoded. An observed whisper.cpp final timestamp exceeded measured PCM by 388 ms; end-token overruns of up to one second are normalized to the actual audio boundary and explicitly flagged uncertain for review. Larger overruns fail. Digital silence is filtered conservatively; quiet speech and overlapping voices still require evaluation.

Temporary source media, PCM and JSON are plaintext in a unique local job directory. Unix directories are explicitly created with mode 0700; Windows inherits the account's temporary-directory access controls. Cleanup is bounded and retries after cancellation on Windows; process crashes may leave files and deletion is not secure erasure. FFmpeg is configured to fail on decoder errors. Complete key recovery, protected production storage, retention/destruction of media and derivatives, remote device/network compatibility, and operational supervision remain unfinished. No real clinical data or local secrets were sent to xAI workers.

## Independent worker review

Three source-only Grok tasks supplied engine implementation, review UI and an independent boundary review. Their reported cost was $1.319962 for this checkpoint. The local ledger records $7.053176 known total including the prior review, plus $200 conservatively reserved for earlier unresolved requests; account billing remains authoritative.

The independent review led to canonical attendance-session binding, version-specific excerpt listing, the forward-only database history rule, stricter decode errors and Unix temporary-directory permissions. Consent rows now lock during checks and job updates include expected-state predicates as additional safeguards. The proposed API consent race and lock inversion did not reproduce in the actual architecture: these paths acquire the same organization advisory lock before record locks, and the worker already locks the job through publication. The proposed blanket eight-character minimum for evidence and mandatory evidence on every clinician-authored field were rejected: legitimate source answers can be short, and manually authored fields remain allowed. Exact substring linkage does not establish clinical correctness; explicit human review is still necessary.
