# Recording-to-reviewed-source implementation contract

Implemented local checkpoint; see [verification and limits](transcript-checkpoint.md). Full objective remains the 50-capability ledger. No clinical data leaves this machine. A local FFmpeg executable decodes saved complete WebM, then the configured whisper.cpp CLI produces timestamped JSON. This is recognition, not a clinical summarizer or verified speaker identification.

Processing is separately authorized: every client in the recorded roster needs a current `consents.kind='transcription'` record. A staff request records a purpose and snapshots those consents; worker start, ongoing processing, save, revision, approval and excerpt creation recheck them. Playback and historical transcript access retain current encounter/clinical scope. Device labels never establish speaker identity.

Persistent jobs: queued/running/ready/failed/cancelled, requested actor/purpose/source track/consent snapshot. One database worker owner, one recognizer per API process shared with the uploaded-WAV endpoint. Interrupted jobs become failed on worker restart; queued jobs revalidate. No automatic retries. Long operations run outside organization locks; authorization/cancellation is polled while running and rechecked under locks before saving. Failed/cancelled jobs never publish partial recognized text.

Server contract:
- GET `/api/telehealth/rooms/{room}/transcripts?track_id={track}` → TranscriptIndex.
- POST `/api/telehealth/rooms/{room}/transcription-jobs` `{track_id,purpose}` → TranscriptionJob, HTTP 202. Current separate transcription consents for all recorded clients required.
- POST `/api/transcription-jobs/{id}/cancel` `{}` → job.
- GET `/api/transcripts/{id}` (optional `?version_id=`) → TranscriptDetail; normal current version or explicitly requested historical version. Excerpts belong only to that selected version and respect patient chart scope. Types in frontend/src/transcriptTypes.ts.
- POST `/api/transcripts/{id}/versions` `{expected_version_id,reason,segments}` → TranscriptDetail. Save a new draft, preserving previous versions. Segment ids unique UUIDs, times nonnegative and inside measured duration, text bounded. Unknown speaker/patient ids rejected.
- POST `/api/transcripts/{id}/approve` `{expected_version_id,attested:true}` → TranscriptDetail. Every included segment requires text, verified participant speaker, resolved uncertainty. Patient association optional; when present requires explicit verified context and cannot assign a client's speech to a different client. At least one included segment required. Reviewed content immutable; corrections create a new draft.
- POST `/api/transcripts/{id}/excerpts` `{version_id,client_id,segment_ids}` → immutable excerpt. Only the current reviewed version; every selected segment must be included, certain, speaker verified and explicitly context verified for this client. Current patient chart permission and encounter association required. Group transcripts are not copied wholesale to patient charts.

Timestamp edits and text corrections remain in immutable version history. Original recognition is immutable. Excerpts identify source version/segments and exact text. No autosign, diagnosis, medication or billing transitions. Empty/no-speech recognition is an empty review draft, never invented words.

Local media engine worker contract (`api/src/media_transcription.rs`): `pub(crate) fn configured()->bool`; `pub(crate) async fn recognize(media:&[u8])->crate::Result<Recognition>`; public(crate) structs `Segment{start_ms:i64,end_ms:i64,text:String,uncertain:bool}` and `Recognition{segments:Vec<Segment>,duration_ms:i64,engine:String,model_label:String,model_sha256:String}` derive Serialize. Use NEXUS_FFMPEG_CLI, NEXUS_WHISPER_CLI, NEXUS_WHISPER_MODEL absolute existing paths. Never take executable paths/args from requests. Return actionable ApiError with static codes, no paths/content/log excerpts. Caller handles semaphore, consent monitoring and cancellation by dropping the future. Subprocesses kill_on_drop.

Decode at most 7201 seconds to 16kHz mono PCM16 WAV segments of 300 seconds. Enforce measured total duration <=7200 seconds without silently truncating, <=24 segments, <=256 MiB input, bounded output JSON/text, and fixed per-process timeouts (decode 120s, each recognition 180s). Use output-json (-oj), fixed language en, no translation/VAD/guessed diarization. Parse numeric offsets.from/to as milliseconds; add the cumulative measured WAV durations. Validate bounds/order; unknown speaker is assigned later by clinician. SHA256 model contents for provenance. Cleanup only the newly created unique job directory, never arbitrary paths; no shell interpolation. Keep temporary media local and document plaintext temporary-file limitations.

Patient documentation linkage:
- GET `/api/clients/{id}/transcript-excerpts` returns up to 100 excerpts from current approved versions, with current clinical patient scope. Historical text access is distinct from permission for a new processing use.
- Form creation/update accepts nullable `transcript_excerpt_id`. A linked excerpt fixes patient/episode/session and exact source text; changing the link clears the editor's answers/provenance; the API requires both fields as an explicit remapped bundle or defaults both to empty. New review/signing/note generation and signing a linked note require its source to remain current and processing consent unchanged. Signed history is preserved.

Primary references: [whisper.cpp CLI](https://github.com/ggml-org/whisper.cpp/tree/master/examples/cli), [FFmpeg downloads](https://ffmpeg.org/download.html), [Windows build provider linked by FFmpeg](https://www.gyan.dev/ffmpeg/builds/). Local installed whisper source confirms JSON offsets are segment timestamps multiplied by 10 (milliseconds). Dependency and model accuracy validation remain distinct from clinical validation.
