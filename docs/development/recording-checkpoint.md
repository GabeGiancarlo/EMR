# Consented recording checkpoint — November 2, 2026

Nexus can request participant agreement during an encounter-linked visit, record each consenting device's microphone/camera, preserve encrypted media in PostgreSQL, and present complete segments through audited clinical playback. This is a local prototype milestone, not complete product acceptance or compliance certification. See the [50-capability ledger](../product/acceptance-ledger.md).

## Implemented behavior

- Administrators and clinical leads author a recording policy with purpose, allowed media mode and retention **review** period. Versions cannot be edited or deleted; they may be retired. Normal workspaces receive no sample policy.
- A request snapshots the policy, admitted/connected roster and each client's current recording-consent record. Every participant, including the clinician, must explicitly accept. Decline/withdrawal leaves the care visit connected. A changed roster, eligibility, consent or policy stops further capture.
- Native MediaRecorder captures each device's own microphone and optionally camera; screen sharing and received peer streams are excluded. The recording badge remains in the sticky visit header. Pause completes the current segment; resume requires previous open segments to finish or time out. Normal pause/end permits 30 seconds to flush the final event. Withdrawal and retired policies reject further uploads, including during that grace period.
- Separate upload-only capabilities are hashed at rest. Ordered chunks are idempotent for identical bytes; changed duplicates/gaps are rejected. Limits: 8 MiB per piece, 16 MiB queued browser media (plus one in-flight piece), 256 MiB per track, 1 GiB per recording, 3,600 pieces per track and 256 tracks per recording. Client calls time out; no unbounded retries.
- Media uses ring AES-256-GCM with random nonces and organization/recording/track/sequence authenticated context. Chunks are append-only. The API reconstructs complete tracks in order and verifies authenticated encryption, checksums, lengths and piece count before playback. Incomplete tracks are visibly incomplete and unavailable for playback.
- The encounter shows earlier rooms, participation events, complete/incomplete recordings and policy management. Completed encounters retain archive access; opening a later room does not hide earlier recordings. Playback requires current clinical role/encounter scope and commits an audit event before returning bytes. Billing/executive users cannot play media.
- `tools/start-api.ps1` configures a 32-byte installation key in ignored `.local/keys/media-v1.key`, protected by Windows ACLs for the current Windows account and SYSTEM. Initialization is idempotent, does not print the key, and refuses to replace an invalid key. An explicitly supplied `NEXUS_MEDIA_KEY_HEX` overrides local loading.

No real camera, microphone, screen, patient or clinical content was captured. Evidence: ignored `.local/design-review/recording-encrypted-playback.png`. Full browser/mobile/device compatibility is not established.

All four complete tracks decrypted byte-for-byte identically through the restored API using the unchanged installation key. This verifies database recovery with that key, not independent recovery after losing the machine/key.

## Remaining work

Timestamped transcription from these recordings, speaker verification, reviewed source versions, AI draft generation and patient-scoped knowledge retrieval are not implemented. Current uploaded-WAV speech functionality remains separate.

Recording is cooperative browser capture, not a trusted media gateway. Polling permits a short client reaction delay; current server checks reject unauthorized subsequent uploads. Abrupt browser/device/network failures can leave incomplete tracks. Unattended cleanup jobs, streaming/range playback, large-media load tests, group mixing, synchronization/seek QA, mobile/Safari support, remote connectivity and production identity remain unfinished.

The local vault retains ciphertext in PostgreSQL and loads a complete track into server/browser memory for playback. Production object storage, KMS/key rotation, protected off-machine key recovery, legal holds, granular disclosure and approved destruction need separate implementation and validation. `retain_until` is a review date, never a promise of automatic deletion. Historical recordings remain restricted care artifacts after capture agreement withdrawal; withdrawal does not silently erase the record.
