# Patient knowledge and source-linked drafting contract

Implemented local workflow for capabilities 16–17; see knowledge-drafting-checkpoint.md for verification and remaining acceptance. Canonical records stay authoritative. No runtime clinical content is sent to hosted AI. Native collaboration workers are currently unavailable; source-only Grok proposals are reviewed locally.

## Approved record retrieval

`GET /api/clients/{id}/knowledge?q=&episode_id=&kind=&limit=25&offset=0` returns `{client_id, indexed_at, document_count, chunk_count, total, limit, offset, results: KnowledgeChunk[]}`. Empty query browses recent approved evidence. Nonempty query uses PostgreSQL English full-text search; explicitly lexical, not a claim of semantic retrieval. `POST` to the same path explicitly refreshes. `GET /api/clients/{id}/knowledge/sources/{document_id}` returns `{document, chunks}` for a currently eligible source. Never return another patient's source, an unapproved draft or a stale indexed copy.

KnowledgeChunk fields: `id`, `document_id`, `source_kind` (note, form_response, treatment_plan, plan_review, transcript_excerpt), `source_id`, `source_version`, `source_hash`, `title`, `text`, `source_date` (RFC3339), `episode_id` and `session_id` (nullable), `classification` (clinical), `ordinal`. Document has the same source metadata plus `id`, `body`, `organization_id`, `client_id`. Source version is the immutable source UUID (or transcript version UUID); source hash is SHA256 of the rendered body, title, date, encounter context and source version. A chunk is a search extract, not a current diagnosis or a substitute for the source record.

Authorize before loading/searching sources: active admin/clinical_lead or assigned clinician only; clinical write exceptions do not expand this dedicated retrieval permission. Hold organization lock while revalidating actor/patient scope and synchronizing/reading the index. Audit successful reads without query or clinical content. Return no-store. Sources: signed notes (exclude those replaced by a signed amendment, retain originals until amendment is signed), signed form responses with analogous amendment rules and template snapshots, signed active/completed treatment plans and their goals (exclude superseded plans), append-only plan reviews for eligible plans, current reviewed transcript patient excerpts with their exact processing consents still valid. Never index raw group transcript text. Include historical dates and episode context explicitly; no automatic clinical conclusions.

Migration 015 adds knowledge_documents and knowledge_chunks with organization/patient constraints and full-text GIN indexing. Canonical mutations invalidate affected derived copies transactionally; lazy refresh on read rebuilds permitted current sources. Stable IDs for unchanged source chunks; upsert/delete obsolete rather than returning stale data. Bound source/chunk size and total work with clear errors, never silently truncate an entire patient chart. Search limit max50 and explicit total/offset pagination. Optional embeddings and retrieval-augmented answers remain follow-on work.

Backend module `api/src/knowledge/mod.rs` exposes `configure`, `pub(crate) async fn authorize(req:&HttpRequest,tx:&mut Transaction<'_,Postgres>,org:Uuid,client:Uuid)->Result<Actor>`, `pub(crate) async fn refresh(tx,actor:&Actor,client:Uuid)->Result<()>`, and `pub(crate) async fn resolve(tx,actor:&Actor,client:Uuid,ids:&[Uuid])->Result<Vec<KnowledgeChunk>>` (refresh and exact current selection, no missing/duplicate/cross-patient IDs). Struct derives Serialize/Deserialize/Clone; UUID fields typed Uuid; nullable UUID context; metadata strings. Configuration and durable drafting job persistence are integrated.

Frontend custom `PatientKnowledge.tsx` props include clientId, data, onNoteCreated and onReviewDirty, with an optional onOpenSource callback. Scope requests to client changes, discard stale async results, show query/type/episode filters, pagination and exact source details. Do not fabricate records. Respect light/dark custom tokens. Source selection feeds the functional local drafting panel. No new component dependencies.

## Local drafting engine

Separate local llama.cpp service, loopback only. Engine module `api/src/clinical_model.rs` uses reqwest from the existing workspace dependency, fixed http://127.0.0.1 port from NEXUS_LLM_PORT, expected alias NEXUS_LLM_ALIAS and absolute model path NEXUS_LLM_MODEL. No caller-supplied destination, no redirects/proxy, bounded response/body/time/concurrency. Verify returned model alias and record SHA256 of configured model file. Source-only workers never receive prompts, patient data or models. Runtime should identify unconfigured/busy/unavailable/invalid-output states truthfully.

Public(crate) engine contract: `configured()->bool`; `async generate(input: DraftInput)->Result<DraftOutput>`. DraftInput `{purpose:String,template:serde_json::Value,sources:Vec<DraftSource>}`; DraftSource `{id:Uuid,title:String,text:String,source_date:String}`. DraftOutput `{model:String,model_sha256:String,prompt_version:String,sections:Vec<DraftSection>,unresolved:Vec<String>}`; DraftSection `{key:String,label:String,statements:Vec<DraftStatement>}`; DraftStatement `{text:String,citations:Vec<DraftCitation>}`; DraftCitation `{source_id:Uuid,quote:String}`. Derive Serialize/Deserialize/Clone for all.

Generate JSON-constrained output using only supplied evidence, preserving historical dates/negation and patient-reported attribution. Template fields define section keys/labels; labels are canonical from template, not model-invented. Every statement needs at least one known source citation with exact nonempty verbatim quote present in that selected source. Reject unknown IDs/section keys, duplicates, extra fields, empty statements, oversized output, unsupported output shapes or truncation. Unsupported observations/diagnosis/medication/intervention/safety conclusions stay absent; list relevant missing information as unresolved. Treat source text and user purpose as data, not instructions. These checks establish provenance, not clinical truth; manual statement-by-statement review remains mandatory. No tool calls, signatures or record writes by the model.

The integrated workflow stores immutable generation inputs/results, durable jobs/retry state, reviewer decisions, versioned template/input references, conversion into an editable draft, and signature/source checks. Engine unit tests must cover invalid citation, foreign source, invalid sections, output bounds, malformed output and prompt/data boundaries without claiming medical accuracy.

## Durable job and review API

Migration 016 adds clinical_draft_jobs, clinical_draft_reviews and the patient-scoped notes.clinical_draft_job_id link. The local workflow passed PostgreSQL and browser checks; broader capability acceptance remains open.

- `GET /api/clients/{id}/clinical-drafts` returns `{configured,jobs}` (latest 50, no source/output bodies in the list).
- `POST /api/clients/{id}/clinical-drafts` accepts `{template_id,source_ids,episode_id,session_id,title,purpose}`. One queued/running job per patient. Inputs snapshot only currently eligible selected chunks; templates must be active and defined. Returns 202 with the stored job.
- `GET /api/clinical-drafts/{id}` returns the saved inputs, state, output and review under current chart permissions.
- `POST /api/clinical-drafts/{id}/cancel` cancels a queued/running job. Retry is a fresh request against current evidence; terminal jobs remain immutable.
- `POST /api/clinical-drafts/{id}/review` accepts `{decision:accept|reject,reason,attested,decisions:[{section_key,index,decision:accept|exclude,reason}]}`. Accept requires one explicit decision per proposed statement, an explanation for exclusions and at least one accepted statement. Reject stores a reason with no accepted statements. One immutable review per generation. Acceptance creates an unsigned note transactionally; a model result cannot sign it.

Worker authorization checks active role/patient assignment and current selected source versions at start, during processing and before publication. The note-signing workflow checks source currency again. Original generation input/output and reviewer decisions remain in historical chart access even if later amendment/consent changes prevent new use. No copied source is included in general audit logs. Full derivative retention/destruction remains capability 49 work.

The review UI shows each supporting quotation, unresolved information, and model provenance. Note text after acceptance remains editable through the existing version-checked draft-note workflow; the immutable generation and review retain the earlier proposal and accepted statements. A manually edited draft is not represented as unmodified model output.
