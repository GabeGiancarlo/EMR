# Recording and review implementation contract

The local capture/storage portion is implemented and verified in the [recording checkpoint](recording-checkpoint.md). Transcript review and the downstream knowledge chain remain unfinished. Advances objective capabilities 13–17; does not shrink the full 50-capability goal.

Recordings belong to an existing telehealth room and preserve its encounter association. No seeded policy or implied blanket consent. An admin/clinical lead authors a versioned policy (title, purpose, retention_days, allow_video); each request snapshots it. The request snapshots every admitted, online participant and each client's current kind=recording consent. Every participant explicitly accepts or declines this request. A refusal never ends the care visit. The host starts only after all accept. Admission/leave/revocation, lost host presence or changed eligibility interrupt capture. Normal host pause/stop permit a bounded final upload; consent withdrawal rejects further media immediately.

Participants record only their own camera/microphone MediaStream, never other guests' received streams or an implicitly selected screen. Browser MediaRecorder emits ordered pieces of a continuous track. Pieces must be concatenated in order before playback; they are not assumed separately playable. Pausing/stopping completes the current track. Resuming opens a new track. Each track has a separate upload-only random capability so a normal visit exit can finish authorized in-flight media after the visit capability closes. It gives no playback/chart access. Incomplete streams remain explicitly incomplete.

Media bytes are AES-256-GCM encrypted using ring (already in the dependency graph), with random nonces and organization/recording/track/sequence bound as authenticated data. Ciphertext and immutable chunk metadata are stored transactionally in PostgreSQL. The local encryption key is separate from database backups. No home-grown cipher, external video SDK, clinical cloud AI, or hosted object-store dependency. This database-backed vault is a local object-storage implementation; production storage/key lifecycle and recovery need separate validation.

Room-scoped clinical access is required for audited playback. Group recordings remain shared encounter artifacts; they are not copied into every patient chart. Transcript review must explicitly verify speaker attribution before patient-specific excerpts can become documentation. Capture time is provenance, never billed duration. Retention expiry does not authorize automatic destruction; holds/approved disposal remain separate lifecycle work.

Evidence: [W3C MediaStream Recording](https://www.w3.org/TR/mediastream-recording/) specifies continuous-recording blob behavior. [ring AEAD](https://docs.rs/ring/latest/ring/aead/index.html) supplies authenticated encryption. [HHS audio-only telehealth guidance](https://www.hhs.gov/hipaa/for-professionals/privacy/guidance/hipaa-audio-telehealth/index.html) distinguishes electronic recording/transcription technologies in its safeguard discussion. These inform implementation; this policy design is not a jurisdiction-specific legal conclusion.
