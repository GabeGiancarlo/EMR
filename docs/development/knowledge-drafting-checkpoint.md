# Approved patient knowledge and local clinical drafting checkpoint

November 2, 2026. This advances capabilities 16–17 of the [expanded objective](../product/acceptance-ledger.md); neither capability nor the complete product is accepted as finished. Authentication remains deferred. Normal-workspace records were not seeded; all new verification records are explicitly synthetic and live in isolated databases.

## Working path

The staff chart now has **Knowledge & drafts**. Authorized clinicians can search approved records by words/phrases, source type and episode, read the source with its date and provenance, and select up to 12 evidence excerpts. Sources include signed notes and forms, signed active/completed treatment plans and their goals/reviews, and current approved patient-specific transcript excerpts. The index does not ingest unreviewed recognition or raw group conversations.

A request snapshots the selected evidence and template. A local llama.cpp service running official Qwen3-4B Q4_K_M weights prepares JSON-constrained statements with exact quotations and unresolved information. The engine checks source IDs, verbatim quotations, template keys, response shape and bounds. This establishes provenance, not semantic entailment or clinical accuracy. No hosted model receives clinical content, and no model calls clinical write tools.

Generation jobs persist queued/running/ready/failed/cancelled states. Current role, assignment, source eligibility and encounter context are checked at enqueue, worker start, during processing, before publication, at acceptance and when the generated note is signed. Inputs and terminal output are immutable. Retry creates a new request; interrupted running jobs fail on worker recovery. One worker owns each database queue and one model request runs per API process.

Review requires a decision on every statement, explanations for exclusions, a review reason and explicit attestation. Acceptance creates an **unsigned** note transactionally; rejection preserves the proposal and reason without creating a note. The note remains editable through optimistic version checks. Signing is separate. Saved proposals/reviews retain the original text even when a reviewer edits the note. Unsaved review choices prevent chart/workspace/operator navigation and browser unloading until recorded or discarded.

## Data and access

Migrations 015–016 add `knowledge_documents`, `knowledge_chunks`, `clinical_draft_jobs`, `clinical_draft_reviews` and the patient/organization-constrained note-generation link, bringing the schema to 42 public tables. Full-text search uses PostgreSQL English word indexing; it is not semantic retrieval or a retrieval-augmented answer service. Unchanged source chunks keep stable identifiers across refreshes. Signed amendments replace their parents in current search, while unsigned amendments do not. Superseded plans and their reviews leave the eligible index. Transcript corrections or invalid processing consent remove their excerpts and linked forms from current search.

Dedicated retrieval/drafting routes allow active administrators, clinical leads and primary-assigned clinicians. Billing/executive roles and unassigned clinicians are denied; resource exceptions do not widen these dedicated permissions. Reads are audited without copying query text or clinical bodies and use `Cache-Control: no-store`. Organization locks serialize eligibility refresh and record changes. Canonical records remain authoritative; derived rows can be rebuilt. Some invalidations conservatively clear the organization's derived index because group consent affects multiple patients.

## Limits

Search is bounded to 1,000 eligible documents, 5,000 chunks per patient, 200,000 bytes per document and 50 results per page. Oversized work fails explicitly; it is not silently truncated. Chunks contain up to 1,200 Unicode characters with 150-character overlap. Index refresh currently scans the patient's eligible source set; large-chart performance and finer invalidation need further work.

Drafting accepts at most 12 sources/template fields and bounded text, has a 120-second model-response timeout, and rejects truncated/invalid output. Generation history currently lists the latest 50 jobs. The local model service has one inference slot shared by the local APIs, while process-level busy controls are separate. Model hashing reads the configured local artifact; the service alias is verified, but this is not remote attestation of the service binary or loaded weights. The runtime is a general-purpose model with no clinical evaluation evidence. Exact citation matching cannot detect an incorrect paraphrase, ambiguous speaker or unsupported interpretation.

Clinical history remains accessible under current chart permission after source changes, even when it is no longer eligible for new generation. Full transitive source-ancestry policy, note correction after upstream changes, sensitive-note segregation, disclosure, derivative retention/destruction, production storage and key protection remain open. Expiry is checked on retrieval; derived copies are not a complete time-driven retention service. No semantic answer assistant, external payer service, portal or authentication provider is supplied by this checkpoint.
